## V5 items

### Record and inspection

- **V5-1. Chained event record.** Each event stores the SHA-256 of the previous event and of its own content (`prev_hash`, `hash`). "Verify the record" recomputes the chain and names the first break. An export and a filing manifest carry the head hash, signed with the application's key (C rule 4; research 2.1 checkpoint signing). Events written before v5 form the start of the chain.
- **V5-2. Refused writes.** Every refusal by the matter store (a human-only action from the agent, a missing record, a bad state) is a row in its own table with actor, action, reason and time. The Matter tab shows the count and the list (C rule 7; research I-15).
- **V5-3. Inspector.** Any record (source, event, draft, revision, authority, provision, argument, review item) opens one panel: its raw form, the events that name it, and its links in and out (C rules 20 and 21; A rule 16).
- **V5-4. Find in the matter.** One full-text index (SQLite FTS5) over source lines, events, draft paragraphs, authorities, provisions, memoranda and arguments. The command bar and the agent search it (E rules 4 and 11).
- **V5-5. Files and jobs.** A Files view lists the matter folder and opens a file with the system. A Jobs view lists the reading jobs, the index jobs and the argument runs; an argument run can be stopped (A rules 14; A11).

### Notebook

- **V5-6. Entities.** Rules extract parties (from cause titles), statutory references, case numbers, amounts and citation mentions from every line, each with its anchor. A Notebook tab lists them. Different amounts or case numbers given for the same item are flagged (G rule 9; H rule 7; research 2.3).
- **V5-7. Corrections and date anchors.** The advocate corrects an event's date or description; the correction is a new version with a reason, and the old version stays readable (H rule 12). A relative date with no base date becomes a review item that asks the advocate for the base date once per file (H rule 13).
- **V5-8. Two OCR readings and disputes.** A scanned page is read twice: by Tesseract and by a second engine (PP-OCR through ONNX Runtime, model files fetched by a vendor script). Critical tokens (digits, dates, amounts, section numbers, citations) must agree. A disagreement is a dispute: the line is marked, an event from it cannot be confirmed, and the advocate decides a reading or types a copy (human-only) (G rules 3 to 7). When the second engine is not installed, pages say "single reading, not cross-checked", as before.

### Research and argument

- **V5-9. Quick check.** For each neutral citation in a draft or authority, the local judgment index is compared with the parties and date the matter records: `found`, `not_found`, `mismatch` (naming the field) or `unavailable` when the year is not indexed. Labelled "Quick check, not verified" everywhere; the gates ignore it (I rules 14 to 16).
- **V5-10. Support, voice and treatment.** Each authority gets a support assessment (`supports`, `partially_supports`, `does_not_support`, `contrary`, `cannot_assess`) and a voice (`holding`, `obiter`, `counsel_submission`, `lower_court_view`, `dissent`, `concurrence`, `unknown`), each a candidate until the advocate confirms it. Treatments record that a later judgment overruled, doubted, distinguished or followed an authority, with bench strength and date. An overruled authority is a review item that blocks the grounds until addressed; doubted or distinguished is a warning; a smaller bench overruling a larger one, or an earlier judgment overruling a later one, is flagged; a missing bench strength or date is a review item, never a guess (I rules 3 to 7).
- **V5-11. Hearing rehearsal.** For the admission hearing: the bench questions most likely to be asked, each with a one-line answer anchored to the record, and opposing counsel's objections (maintainability, limitation, delay, alternative remedy, distinction). Made by the same checked model calls as the argument loop. A challenge register keeps generated challenges, verified defects and challenges the advocate accepted apart (research M6). No outcome is predicted.
- **V5-12. Bench trends (advisory).** From the judgment index: the share of indexed Supreme Court judgments by disposal, by year. Labelled advisory and descriptive. No score is computed for the matter and no judge is named (workflow 7E; ruling R-1). It never enters a draft.

### Drafting, verification and filing

- **V5-13. Compare revisions and Word.** Any two revisions of a draft can be compared paragraph by paragraph (J rule 18). A revision can be opened in Microsoft Word (or the system's DOCX application) as a copy; the edited copy is imported back as a new revision (research 2.7).
- **V5-14. Citation and reference hygiene.** Text that looks like a citation but has no neutral form (SCC, AIR, SCR, "v.", "Civil Appeal No.") is a review item asking for the neutral citation (K rules 1 and 7). Statutory references in a draft are compared with the matter's provisions; one recorded as repealed is a defect (K rule 9).
- **V5-15. Victim identity.** The advocate marks a matter as one where a victim's identity is protected and lists the names. A draft that contains a listed name is a defect, and the filing set is refused while it remains (K rule 14).
- **V5-16. Limitation with exclusions.** The advocate records when the certified copy was applied for and received; the time between is excluded and shown in the working. The source of the exclusion is recorded as given by the engineer, to be confirmed by the owner (K rule 13; questions.md Q-7).
- **V5-17. AI-use disclosure and the paper book.** The filing set gains the AI-use disclosure: which assistance was used, every citation with its validator outcome, and every attestation in its own section, never as verified. It is refused while a citation is blocked (ruling R-3; L rule 3; C rule 17). The filing set also gains one paper book PDF: an index page with page numbers, every document in order, page numbers stamped, and bookmarks (J rule 9; M9). A conversion check compares each PDF's text with its approved DOCX paragraphs (K rule 18).
- **V5-18. Uncertain portal result.** A submission whose result is not recognised is `unknown`. Before another attempt, the advocate reconciles it (submitted with a diary number, or not submitted); a new attempt needs new confirmations (L rule 9).

### Practice

- **V5-19. Hearings, orders and impact.** The advocate records a hearing: date, bench, directions and the next date, confirmed or inferred. A new order added after a draft was approved opens a review item naming the approved drafts to re-check (research M10).
- **V5-20. Docket and reminders.** The home page lists every matter with its stage, next date, next deadline and open items. Reminders with a date and time raise a system notification while the application runs (research M11, M13).
- **V5-21. Usage, budget and confidentiality.** Each agent run records its tokens and cost and the matter shows the totals. A matter can have a budget: the agent stops before a run that would pass it. A matter marked confidential uses only local models, and its web queries are refused (D rules 13 and 17).
- **V5-22. Stop a run.** The chat has a Stop button that ends the agent's run between steps.
- **V5-23. Contacts.** A firm contacts list (clients, opposing parties, advocates) in the user data folder. Matter parties link to contacts with their role and the name as it appears in the record. Creating a matter for a new client asks for confirmation (O rules 1 to 3; A rule 4).
- **V5-24. Questions for instructions.** A document of the questions the matter still needs answered: missing details, unresolved dates, disputed readings, open review items, open critical questions (research M2: instruction gaps).
- **V5-25. Diagnostics and crash dumps.** "Make a diagnostics file" lists exactly what it will contain (versions, settings without secrets, recent logs), and writes it only on request. Crashes write a local dump; nothing is uploaded (P rule 7; Q rule 7).

## Proof task

On a real brief the owner: verifies the record chain after a day's work; finds a phrase with Find; resolves an OCR dispute; corrects one event; quick-checks the citations; records one treatment; runs a rehearsal; compares two revisions; records the certified copy dates; makes a filing set with the disclosure and the paper book; records a hearing; and sees the matter on the docket.
