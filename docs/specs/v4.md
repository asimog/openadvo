## V4-1. Research sources

Four sources, each a plain library behind one interface (`search`, `read`). What each returns says where it came from.

- **Supreme Court judgments, AWS Open Data** (`indian-supreme-court-judgments`, CC BY 4.0). The metadata of each year (`metadata/parquet/year=YYYY/metadata.parquet`: title, parties, judge, citation, INSC number, CNR, decision date, disposal, path) is read by HTTP range requests and kept in a local full-text index in the user data folder (`corpus.db`, SQLite FTS5). The advocate chooses the years to index. A judgment's PDF (`data/pdf/year=YYYY/english/<path>_EN.pdf`) is fetched when it is read, kept in the user data folder by SHA-256, and read with page and line numbers like a source.
- **High Court judgments, AWS Open Data** (`indian-high-court-judgments`). The advocate chooses a court and a year. The metadata of every bench of that court in that year is read (title, CNR, judge, decision date, disposal, PDF path) into the same index. PDFs are fetched and read the same way.
- **India Code** (`indiacode.gov.in`, the DSpace REST API). Search returns Acts, sections, rules and orders. A section is read with its Act, number, text and the repealed flag. India Code gives the current text: the version in force on the governing date is not computed, and the advocate confirms which version applies (ruling R-4).
- **The web.** A keyless web search and a page fetch that returns the page text. Web results are for discovery only. They never verify a citation (ruling R-6).
- Every query to a source outside the computer is an event in the matter (source and query text). Settings has one switch per source; each is on until the advocate turns it off. A source that is off, or cannot be reached, says so; it never returns an empty result as if nothing were found.

## V4-2. Saving what research finds

- A judgment from either AWS set can be saved to the matter as an authority (candidate, with its citation, parties and date from the metadata, and the paragraph and proposition the advocate or the agent gives). The judgment's page and line can be quoted like a source line.
- A section from India Code can be saved to the matter as a statutory provision (Act, section, text, repealed flag, retrieved date).
- The agent gets the tools `search_judgments`, `read_judgment`, `search_statutes`, `read_statute_section`, `web_search` and `web_fetch`. Saving an authority still goes through `add_authority` (a candidate). Saving a provision is `save_provision` (a candidate). The advocate adopts or rejects.

## V4-3. The argument loop (comparable to MOTO, built here)

For one accepted issue, the loop runs a fixed number of rounds (default 2, at most 4). Each round:

0. **Reply** (from round 2). Counsel for the attacked side answers each attack of the last round (at most four), as a rebut, undercut or undermine of that attack. A reply passes the same code checks. A grounded reply that stands defeats its attack, and the computed status shows it.
1. **Generate.** Several generator calls (default 3) run in parallel. Each is given a different target cell of the archive (a ground type: jurisdictional, procedural, evidentiary, statutory, constitutional, precedent; and a stance: petitioner or respondent) and the last five typed rejections of that cell. The context is assembled by code from the records only: the issue, the confirmed events with their ids, the matter's authorities and provisions with their ids, and the open weak points. Each call returns candidate arguments as JSON: claim, reasoning, the record events it relies on (with a quote), the authorities (with paragraph), and the provisions.
2. **Validate in stages.** Code checks first; a failed check rejects the candidate with a typed reason:
   - `MODEL_ERROR`: the model call failed; the error is recorded.
   - `SCHEMA`: the JSON is not a valid argument.
   - `UNGROUNDED_FACT`: a cited event is not a confirmed event, or its quote is not in the event's line.
   - `UNKNOWN_AUTHORITY`: a cited authority is not an authority of the matter.
   - `FAILED_CITATION`: the validator found the authority's citation failed and the advocate did not attest it.
   - `REPEALED_PROVISION`: a cited provision is recorded as repealed.
   - `DUPLICATE`: at least 60 per cent of its word sequences are in an argument already in the archive.
   - `NO_GROUNDING`: it cites no event and no authority.
3. **Critique.** For each survivor, one critic call lists the critical questions the argument does not answer (for its scheme: from precedent, from statute, from the record). One opposing-counsel call writes attacks on it (rebut, undercut or undermine), and each attack passes the same code checks before it enters the archive with an attack link.
4. **Compare.** Within a cell with two or more arguments, a judge call compares pairs on grounding and clarity only, and an Elo rating per argument is updated. The rating orders the cell. It is not a probability and not a prediction.

Rules of the loop:
- The status of every argument (in, out or undecided) is computed by code from the attack links by grounded semantics. No model asserts it.
- No win probability, outcome estimate, judge tendency or party-conduct prediction is produced (ruling R-1; C1 section 3.13).
- Every model call's request and response are saved in the matter folder (`studio/<run>/`), with their SHA-256 in the run record.
- When no model is available, the loop does not run and says so.

## V4-4. The Studio

- The Research tab becomes the **Studio**, with four parts: **Conference** (the issues, authorities, citation checks, adverse-authority review and memoranda, as before), **Search** (one search box, the source chosen per search, results with their origin, read a judgment page by page or a section, save), **Arguments** (run the loop for an issue; the archive as a grid of ground type by stance; each argument with its grounding, validator results, critical questions, attacks, rating and computed status; accept or reject, human-only) and **Research log** (every query and every run).
- An accepted argument can be sent to the Grounds draft as a tracked insertion that the advocate keeps or undoes (step 5 flow).
- The **weak-points report** lists, for every accepted argument, its unanswered critical questions and its attacks that are not defeated. It is a section of the conference package.

## Not in v4

Point-in-time versions of statutes, treatment edges between judgments (followed, distinguished, overruled), Indian Kanoon, and a second validator family for propositions stay in [../parking.md](../parking.md).

## Proof task

On a real brief, the owner indexes the Supreme Court years needed, finds and saves two authorities and one provision, runs the loop for one accepted issue, accepts one argument and rejects one, sends the accepted one to the Grounds, and reads the weak-points report in the conference package.
