# Decision register: Phase 5 RAG pipeline

Date: 2026-11-16. Revised 2026-11-18. Status: proposed. Only the owner accepts a decision. This file records the recommendation from [../logs/2026-11-18-rag-integration-phases.md](../logs/2026-11-18-rag-integration-phases.md), [../logs/2026-11-16-phase-5-rag-assessment.md](../logs/2026-11-16-phase-5-rag-assessment.md) and [../logs/2026-11-16-phase-5-rag-integration.md](../logs/2026-11-16-phase-5-rag-integration.md). It does not edit [../../docs/decisions.md](../../docs/decisions.md).

Revision 2026-11-18: combines the 18 November consolidated brief and the owner's instruction: **TypeScript only, no Rust Kernel**. RAG-24 to RAG-33 are added. RAG-0 is the only RAG integration phase in this step; RAG-1 to RAG-5 are deferred.

New decisions overrule old decisions only when the owner accepts them. Until then, the accepted decisions stay as they are.

| Id | Decision | Why | Rejected | Status |
|---|---|---|---|---|
| RAG-1 | The canonical stores stay SQLite. No server, no Docker, no cloud dependency. | Decisions 8, 9, 12 and 13. The advocate's machine is the constraint. | PostgreSQL, SQL Server, a hosted vector database, a local server. | Proposed |
| RAG-2 | One retrieval function over seven scope adapters: statute, procedure, research, matter, firm, advocate, session. | One contract, one result shape, one coverage report. The agent sees one tool, not seven. | A separate memory server, a separate search service, ad-hoc SQL tools. | Proposed |
| RAG-3 | Statutes, rules, regulations, notifications and practice directions are provision rows. Akoma Ntoso 3.0 is the export and exchange form, not the primary store. | Queries need rows and indexes. XML is for audit, sharing and standards. | Akoma Ntoso as the primary store; a document-only store. | Proposed |
| RAG-4 | Chunk by legal boundary: section, article, rule or order. A long provision splits at its own sub-section, clause, sub-clause, proviso, explanation, illustration or exception. Never by page length or token count. | The citation unit is the legal provision. A token window breaks the citation. | Fixed 512/1,024-token windows; page-size chunks. | Proposed |
| RAG-5 | Every chunk carries a structured citation key: instrument, kind, number, chapter, part, order, sub, clause, proviso, version. | The key is the id, the anchor and the audit key. A display string alone cannot be verified. | A free-text citation field only. | Proposed |
| RAG-6 | Chapter and part maps come from the source PDF's arrangement or index, with a small curated map per Act. An unmapped provision says `unmapped`. | India Code has no chapter field; `no_of_chapter` is unreliable. A wrong chapter is worse than none. | Inferring a chapter from a section number; a model guessing. | Proposed |
| RAG-7 | The judgment paragraph is the research unit; the judgment is the parent. A long paragraph splits at sentence boundaries, and the citation stays the paragraph. | An advocate cites a paragraph, not a token window. | Judgment-level chunks; fixed-size chunks. | Proposed |
| RAG-8 | Default retrieval is exact lookup + FTS5 + graph + filters. Vectors join only when a local model is installed. | Legal search needs exact phrases, citations and treatment first. It works offline with no model. | Vector-first retrieval; a model-only query agent. | Proposed |
| RAG-9 | Vectors are optional. The default vector index is a flat Float32 index in TypeScript. sqlite-vec is optional. usearch or LanceDB is benchmarked only past the measured threshold. | 10-43 ms at 20k-100k vectors; no native binary; one module. | Qdrant, Chroma, Milvus, Weaviate, pgvector, LanceDB as default. | Proposed |
| RAG-10 | No graph database in Phase 5. The three graphs are SQLite edge tables with recursive CTEs. LadybugDB is an optional derived index only after a measured graph-query failure. | Decisions 12 and 13. Our walks are two or three hops. A second store must justify itself. | Neo4j, Memgraph, FalkorDB, Kuzu (archived), LadybugDB as the source. | Proposed |
| RAG-11 | Verification at the time of use: re-read the exact source, normalize, hash, compare. `verified`, `changed` or `unreachable`. `unreachable` is unconfirmed, never passed. | Decision 16 and ruling R-4. A stale row must not look verified. | A weekly bulk refresh only; trusting `last_modified`; showing stale as verified. | Proposed |
| RAG-12 | Research is quote-first: retrieve, select exact quotes, verify quotes, reason only over verified quotes, verify citations deterministically, then review. | The model must not invent a quote or a citation. A deterministic gate catches it. | Answer-first RAG; a model citing from memory; a single model that grades itself. | Proposed |
| RAG-13 | Multi-agent roles run inside one skill run: fact extraction, retrieval, quote selection, reasoning, citation verification. The Matter Agent orchestrates. | Separate contexts, one budget, one step log, one human gate. | Five long-lived agents; a separate agent server; the agent approving its own run. | Proposed |
| RAG-14 | The firm database, each matter database and the session logs stay separate files. The firm database holds advocate details, basic matter pointers and the firm agent log. | The owner's instruction. One writer per store. No cross-matter facts. | One database for all; session logs inside `matter.db`; a shared matter database. | Proposed |
| RAG-15 | The matter database and the session logs are append only. Compaction starts a new session segment with a summary; the old segment is never edited. | The owner's instruction. A log is evidence. | In-place updates; deleting old turns; one endless session file. | Proposed |
| RAG-16 | Law, firm knowledge, research notes and memos are versioned and shareable. Matter facts are append-only and never shared. | Law and know-how are public or firm property; facts are client property. | Editing law in place; sharing matter facts through the firm library. | Proposed |
| RAG-17 | Plan review is native, on the Plannotator pattern: comment, replace, delete, insert, global note, threads, one structured message to the agent. Annotations live with the target. | The pattern is right; the browser extension is not. The review must be in the matter file. | Bundling the 53 MB Pi extension; a separate review server; email-style comments. | Proposed |
| RAG-18 | No RAG platform and no vector/graph server in Phase 5. RAGFlow, WeKnora, Onyx, GraphRAG and LightRAG are references, not runtimes. | A platform brings a second store and a schema that does not fit. | Adopting WeKnora or RAGFlow; running Neo4j; running Qdrant. | Proposed |
| RAG-19 | Build the adapters now, in one piece, with contract tests. Do not ship a query agent alone and do not build a platform. | A query agent alone cannot supply citation keys, versions, scope or audit. Piecemeal features duplicate retrieval. | A file-grep agent only; ad-hoc SQL tools; a full RAG product. | Proposed |
| RAG-20 | The Phase 5 exit is a real research memorandum the owner completes: adverse authority found, binding effect explained, the provision in force on the governing date, coverage stated. | Lesson L3: done means the owner completed a real task. | A green test suite; a demo; a document the agent wrote. | Proposed |
| RAG-21 | A large judgment index is partitioned by court and year (or a five-year bucket), with a catalog and a coverage line. No single global FTS or vector table at 1M paragraphs. | Measured: one 1M-row FTS table takes 118 ms for a phrase and 464 ms for an OR query; a 50,000-100,000-row partition returns a phrase query in about 10-20 ms. The target is p95 under 150 ms. | One global index; a server-side search engine; a vector-first design. | Proposed |
| RAG-22 | A long case file, judgment or memo is indexed by its own structure. The page is an anchor, not a chunk. A judgment with more than one opinion gets one paragraph namespace per opinion. | A 100-page file is 300-1,000 paragraphs; search is fast. The hard parts are OCR, layout and anchoring. A concurrence can restart paragraph numbering. | Page-size chunks; token windows; one paragraph sequence for the whole judgment. | Proposed |
| RAG-23 | FTS5 uses external content, indexed metadata columns and `detail=full`; bulk loads run `optimize`. Metadata filters never use `UNINDEXED` FTS columns. | One text copy; phrase search works; a SQL filter on an `UNINDEXED` column took about 1 s at 1M rows. | Duplicating text in the FTS table; `detail=none`; filtering on `UNINDEXED` columns. | Proposed |
| RAG-24 | A formal legal ontology is deferred. Use stable IDs, typed relationships, controlled relation names and source-backed edges now. | The ontology is not a Phase 5 prerequisite. A model-generated ontology must never become authority. | Building an ontology before retrieval; a model-generated ontology as the source of truth. | Proposed |
| RAG-25 | Pi remains the current harness. Deep Agents, DocAtlas and other projects are references, not a second runtime. | One application, one harness, one approval path. | A second agent loop; a RAG platform with its own agent. | Proposed |
| RAG-26 | **TypeScript only. No Rust Kernel.** The current repository is Electron/TypeScript (decision 1). The 18 November brief's Rust direction is rejected for this work. | Owner instruction, 2026-11-18. The code in front of the agent is TypeScript. | A Rust Kernel; a parallel Rust runtime; porting the skeleton before the report is accepted. | **Owner instruction, 2026-11-18** |
| RAG-27 | Verification dimensions stay separate: source, text, currentness, citation, quote, support and treatment. No single `verified` badge claims all seven. | A file hash proves the file did not change; it does not prove current law or quote support. | One `verified` boolean; a green badge for a changed or unreachable source. | Proposed |
| RAG-28 | Store authority facts (court, jurisdiction, bench, date, territory, role, treatment). Do not reduce authority to one number; keep relevance and adverse authority visible. | A higher court on a different issue must not automatically outrank a directly relevant authority. | `3/2/1` authority score as the binding decision. | Proposed |
| RAG-29 | Retrieval uses bounded concurrency and per-adapter timeouts. A failed or deferred scope is recorded in coverage; a partial search is labelled partial. | A slow adapter must not block the others. A bounded search must not claim completeness. | Sequential adapter loop; silent truncation; an exhaustive label on a partial search. | Proposed |
| RAG-30 | The retrieval agent reads and proposes. It never writes canonical facts, legal edges, approvals or propositions. | The canonical stores and the advocate own authority and confirmation. | Agent writes to `matter.db` or `corpus.db`; agent confirms its own edge. | Proposed |
| RAG-31 | Dynamic FTS partition names come from a trusted allowlist. Vector identity includes model, version and dimensions, plus the source text hash. | Prevent SQL identifier injection; prevent stale or cross-model vector reuse. | User-provided table names in SQL; `(scope, id)` as the whole vector key. | Proposed |
| RAG-32 | Commentary is secondary material. Index its structure and passages, but never rank it as binding law or mix it with statutory text. | Commentary helps understanding; it is not the statute or the judgment. | Commentary in the statute scope; commentary edges that change binding status. | Proposed |
| RAG-33 | RAG-0 (contract and skeleton) is the only RAG integration phase in this step. RAG-1 to RAG-5 are deferred to their owning product phases. | Owner instruction: report and integration first; the rest can wait until the other phases are done. | Building the full RAG now; firm/advocate/session/scale/review before their phases. | Proposed |

## Phase mapping

| Phase | Scope | Status |
|---|---|---|
| RAG-0 | Contract, registry, scope guard, bounded retrieval, coverage, health, statute/procedure/research/matter adapters, quote verifier, deferred placeholders, tests | In this step |
| RAG-1 | Law data: 28+3 instruments, repealed codes, rules PDFs, chapter maps, Akoma Ntoso export, verification at use | Deferred to Phase 5 module work |
| RAG-2 | Research: plan, quote-first, adverse search, memo, review | Deferred to Phase 5/6 module work |
| RAG-3 | Firm, advocate and session scopes; annotations; append-only migration | Deferred to Phase 10/12 |
| RAG-4 | Court/year partitions, external-content FTS, multi-opinion paragraphs, optional vectors/ANN | Deferred until measured need |
| RAG-5 | Plannotator-style review, chamber sharing, golden set and hardening | Deferred to Phase 6/12/13 |

**Recommended acceptance position:** accept RAG-1 to RAG-8, RAG-10 to RAG-25, RAG-27 to RAG-33. Accept RAG-9 only as a benchmark-gated option. Accept RAG-21 only with the coverage rule. RAG-26 is the owner's instruction of 2026-11-18.
